# Файлы уроков

Файл относится к существующему уроку с сохранённой темой. Метаданные находятся
в `lesson_attachments`, содержимое — в отдельном закрытом бакете MinIO.
Идентификатор объекта генерируется сервером и не зависит от имени файла.
В ответах API отсутствуют ключи объектов, адрес MinIO и ключи доступа.

## Доступ

Ответственный учитель использует персональные `can_view_lesson` для чтения
и `can_update_lesson` для загрузки и удаления. Эти же операции доступны
администратору с соответствующим разрешением. Проверка назначения учителя
выполняется отдельно от проверки permission: после замены прежний учитель
не сохраняет доступ к файлам.

Родитель читает список и скачивает файл через маршрут с `studentId`.
Проверяются роль parent, `can_view_user` и `can_view_journal` для одного ученика,
его роль student, принадлежность нужному классу и вхождение даты урока
в период зачисления. Родитель не может загружать и удалять файлы.

Родитель видит имена файлов сразу в карточке урока и скачивает их нажатием.
В расписании поле `homeworkLessonId` указывает на тот же предыдущий урок,
по которому выбирается домашнее задание. Оно заполняется и при пустом тексте
задания, но не у повторных занятий предмета в день. Списки загружаются через
родительский endpoint с проверкой доступа; пустой список скрывает блок файлов.

Файлы выдаются через API, чтобы каждый запрос проходил актуальную проверку
прав. Публичные и подписанные ссылки MinIO не выдаются. Ответ скачивания имеет
`Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`
и `Cache-Control: private, no-store`. Имя очищается от путей и управляющих символов;
тип определяется сервером по содержимому. Размер ограничен 20 МиБ.

## Согласованность PostgreSQL и MinIO

Загрузка: service открывает транзакцию, domain проверяет доступ и создаёт
метаданные, service записывает объект и завершает транзакцию. При ошибке
загрузки или коммита выполняется компенсирующее удаление объекта с отдельным
коротким контекстом, работающим и после отмены HTTP-запроса. Ошибка компенсации
попадает в серверный лог. MinIO и PostgreSQL не образуют распределённую транзакцию.

Удаление: domain ставит `deleted_at`, service коммитит транзакцию и только затем
удаляет объект. Список и скачивание сразу исключают удалённый файл. При сбое
MinIO запрос возвращает `503`; интерфейс сохраняет кнопку повторной попытки.
Повторный DELETE с тем же ID снова проверяет права и повторяет удаление объекта.
Метаданные остаются как отметка удаления. Фонового сборщика объектов нет;
при ошибках компенсации или прерванном удалении очистка выполняется оператором.

Настройка переменных S3, миграции и лимита reverse proxy описана в README
и `deployment.md`. Production-секреты не входят в исходный код.
