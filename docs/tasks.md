# План задач Journal MVP

> Прогресс: выполнено 25 из 46 задач, осталось 21.

## Правила выполнения

- Один пункт ниже — один самостоятельный коммит.
- Размер коммита — не более 500 изменённых строк с учётом тестов, миграций и
  сгенерированного OpenAPI-кода.
- Если во время реализации оценка превышает 500 строк, задача делится по слоям
  или по одному пользовательскому сценарию без смешивания несвязанных изменений.
- Серверные изменения выполняются в порядке `OpenAPI -> api -> service -> domain
  -> repository`; бизнес-правила и доступ обязательно покрываются тестами.
- Клиент получает и изменяет данные только через API. Временные моковые данные
  удаляются по мере подключения соответствующего сценария.
- После каждого коммита запускаются проверки затронутой части. Перед завершением
  этапа запускается полный набор проверок клиента и сервера.
- Оценка размера является ориентиром и включает production-код и тесты.

## Порядок этапов

Задачи выполняются последовательно внутри каждого раздела. Между разделами
допустима следующая параллельность после завершения основы T01–T03:

1. T04–T09 подготавливают административные справочники.
2. T10–T20 формируют классы и назначения; они обязательны для кабинета учителя.
3. T21–T23 можно выполнять параллельно T10–T20 после готовности проверки
   объектных разрешений.
4. T24–T35 составляют рабочий журнал учителя.
5. T36–T42 используют готовые учебные данные для родительского журнала и итогов.
6. T43–T46 завершают интеграцию и проверяют MVP целиком.
