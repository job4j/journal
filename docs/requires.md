# Journal

## Смысл проекта

Journal — электронный журнал для семейных классов.

Проект помогает учителям вести уроки, домашние задания, оценки,
комментарии и учебные материалы. Родители получают персональный доступ
к информации только о своих детях.

Система рассчитана на многолетнее использование. Переход в новый
учебный год или следующий класс не должен требовать копирования проекта,
изменения кода или создания отдельной системы.

## Пользователи

В системе предусмотрены четыре основные роли:

- Администратор управляет учебными годами, классами, учениками,
  родителями, учителями и предметами.
- Учитель создаёт уроки, указывает темы и домашние задания,
  прикрепляет материалы, создаёт проверочные работы и выставляет оценки.
- Родитель видит расписание, задания, оценки и комментарии только
  для своих детей.
- Ученик является пользователем системы и входит в состав учебного класса.

В будущем могут появиться роли ученика и руководителя центра.

## Основные сущности

- Учебный год
- Класс или учебная группа
- Ученик
- Родитель
- Учитель
- Предмет
- Зачисление ученика в класс
- Назначение учителя на предмет
- Урок
- Тема урока
- Домашнее задание
- Учебный материал
- Проверочная работа
- Оценка
- Комментарий учителя
- Пропуск занятия

## Принципы предметной области

- История обучения и оценок должна сохраняться по учебным годам.
- Ученик может переходить между классами и группами.
- В семье может быть несколько детей.
- У ребёнка может быть несколько родителей или представителей.
- Учитель может вести несколько предметов и классов.
- На одном уроке может не быть оценивания или может быть несколько работ.
- Работа имеет тип: домашняя, на уроке, проверка знаний или другой тип.
- Система не должна быть жёстко привязана только к пятибалльной шкале.
- Материалы в первой версии хранятся в виде внешних ссылок.
- Родитель не должен получать данные других семей.

## Связь класса, предмета и учителя

Предмет создаётся один раз в общем справочнике, например «Математика» или
«Русский язык». Затем предмет отдельно добавляется в каждый учебный класс.

Связь предмета с классом содержит ответственного учителя. Поэтому один предмет
может преподаваться в разных классах разными учителями:

```text
Математика -> 7 класс -> учитель Иванов
Математика -> 5 класс -> учитель Петрова
```

Назначение учителя относится не к предмету вообще, а к предмету в конкретном
классе. В одном классе нельзя дважды добавить один и тот же предмет. В первой
версии у предмета класса только один ответственный учитель.

## Основные пользовательские сценарии

### 1. Первичная настройка администратором

Администратор входит в систему и:

1. Создаёт учебный год, указывая название, дату начала и дату окончания.
2. Создаёт пользователей и назначает им роли администратора, учителя,
   родителя или ученика.
3. Создаёт учебные классы внутри выбранного учебного года.
4. Наполняет общий справочник предметов.
5. Добавляет предметы в классы и назначает ответственному учителю каждый
   предмет конкретного класса.

Только пользователь с ролью учителя может быть назначен ответственным за
предмет класса. Один учитель может вести несколько предметов и несколько
классов.

### 2. Формирование учебного класса

Администратор открывает класс выбранного учебного года и:

1. Добавляет в класс пользователей с ролью ученика.
2. Добавляет в класс предметы из общего справочника.
3. Для каждого добавленного предмета назначает ответственного учителя.
4. Может просматривать текущий состав класса и список назначенных предметов.
5. Может вывести ученика из класса, сохранив дату выбытия и историю его оценок.

Ученик может находиться в классах разных учебных лет. История состава класса
не удаляется при переходе ученика в следующий класс.

### 3. Работа учителя

Учитель входит в систему и:

1. Видит только те классы, в которых ему назначен хотя бы один предмет.
2. Внутри класса видит только назначенные ему предметы.
3. Открывает предмет класса и создаёт урок с датой, темой и домашним заданием.
4. Прикрепляет к уроку ссылки на учебные материалы.
5. Создаёт одну или несколько оцениваемых работ: домашнюю работу, работу
   на уроке, проверку знаний или другой тип работы.
6. Выставляет оценки только ученикам, входящим в этот класс.
7. Добавляет или изменяет комментарий к оценке.

Учитель не может создавать уроки и оценки для предметов, на которые он не
назначен ответственным. Выбывший ученик остаётся в истории, но после даты
выбытия ему нельзя выставлять новые оценки.

### 4. Работа родителя

Администратор связывает родителя с учеником, назначая родителю два персональных
разрешения. В `value` каждого разрешения записывается UUID пользователя-ученика:

- `can_view_user` разрешает видеть ученика в списке и открывать его профиль;
- `can_view_journal` разрешает видеть учебные данные этого ученика.

После входа родитель:

1. Видит список только тех учеников, для которых у него есть активное
   разрешение `can_view_user` с UUID ученика в `value`.
2. Выбирает ученика из списка.
3. Видит учебные годы и классы, в которых состоял ученик.
4. Выбирает учебный год или класс.
5. Видит предметы этого класса.
6. По каждому предмету видит уроки, оцениваемые работы, оценки и комментарии
   учителей.

Перед выдачей доступа система должна проверить, что UUID из `value` относится
к пользователю с ролью ученика. Для просмотра табеля одновременно требуются
`can_view_user` и `can_view_journal` с UUID одного и того же ученика.

Назначение и отзыв этих двух разрешений выполняются одной операцией. Родитель
не должен видеть пользователя или учебные данные, если соответствующее
персональное разрешение отсутствует или относится к другому UUID.

## Разрешения в пользовательских сценариях

Разрешение состоит из `code` и необязательного `value`.

- `value = NULL` означает доступ ко всем объектам соответствующего типа.
- Конкретный UUID в `value` ограничивает разрешение одним объектом.
- Глобальные разрешения могут назначаться через роль.
- Персональные разрешения назначаются пользователю напрямую.

При назначении учителя на предмет класса система должна выдать ему разрешения
на просмотр класса и предмета класса, а также на работу с уроками и оценками
этого назначения. UUID соответствующего объекта записывается в `value`.
Изменение или удаление назначения должно синхронно изменить эти персональные
разрешения.

Связь родителя с учеником хранится как персональные permissions, назначенные
через `user_permissions`. Отдельная таблица связи родителей и учеников не
используется. Разделение `can_view_user` и `can_view_journal` позволяет выдать
доступ к профилю ученика без автоматического доступа к его учебным данным.

## MVP

Первая версия должна поддерживать:

- авторизацию;
- роли администратора, учителя, родителя и ученика;
- учебные годы и классы;
- учеников и связь с родителями;
- учителей и предметы;
- создание уроков;
- темы уроков и домашние задания;
- ссылки на учебные материалы;
- создание оцениваемых работ;
- оценки и комментарии;
- пропуски занятий;
- журнал учителя;
- персональный журнал ребёнка;
- просмотр истории по учебным годам.

## Не входит в первый MVP

- мобильное приложение;
- собственное файловое хранилище;
- видеоконференции;
- Telegram-бот;
- автоматическая генерация оценок;
- сложная аналитика;
- интеграции с государственными образовательными системами.
