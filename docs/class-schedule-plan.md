# Расписание класса по неделям

## Подзадачи и порядок работы

Подзадачи выполняются последовательно. Доступ для учителя и родителя
в текущую задачу не входит.

1. **Требования и расшифровка исходного расписания — согласованы.** Заполняются
   все недели 2026/2027, включая каникулы. Основная программа привязана к
   предметам класса, внеурочные занятия допускают свободное название и примечание.
2. **Модель данных и миграция схемы — выполнено.** Расписание принадлежит классу,
   а через класс — учебному году. Каждая календарная неделя независима.
   Схема не должна создавать общие изменяемые записи для всех недель.
3. **Сервер и контракт API — выполнено.** Просмотр и изменение выбранной недели;
   серверная проверка прав администратора, класса, дат и времени.
   Изменения выполняются транзакционно. Контракт OpenAPI обновляется
   до реализации обработчиков. Тесты проверяют отказ в доступе для
   неавторизованного пользователя, учителя и родителя, валидацию и
   независимость соседних недель.
4. **Интерфейс администратора — выполнено.** Вход из карточки класса, выбор недели,
   переход назад/вперёд и к текущей неделе, сетка дней и занятий,
   добавление, изменение и удаление занятия в выбранной неделе.
   Перед сохранением явно видны класс и даты редактируемой недели.
5. **Начальное заполнение 7 класса — выполнено.** Отдельная миграция данных копирует
   согласованную таблицу в даты учебного года 2026/2027, включая каникулы.
   Уже изменённые недели не перезаписываются последующими обновлениями.
6. **Проверки и документация — выполнено.** Интеграционные проверки миграций и API,
   пользовательские сценарии переключения и изменения недели,
   линтеры, сборки и инструкция применения.

## Инварианты

- Неделя — понедельник–воскресенье по календарным датам учебного года.
  Недели на границах года могут быть неполными; занятия должны оставаться
  внутри дат учебного года своего класса.
- Изменение одной недели не меняет остальные недели.
- Расписание — план занятий. Оно не создаёт и не редактирует уроки,
  работы, оценки и посещаемость в существующем журнале.
- Права проверяются сервером на каждом запросе. Отсутствие кнопки
  у учителя или родителя само по себе не ограничивает доступ.
- Для занятий по группам могут потребоваться несколько записей
  на один день и номер урока; нельзя заранее считать это дубликатами.
- Миграция схемы и миграция начального заполнения — отдельные изменения.

- Внеурочные занятия сохраняются без связи с предметом, с названием и примечанием.
- Среда, урок 5: классный час отмечен «1 раз в месяц», шахматы — «до 14:00».

не генерируется. Для физкультуры девочек фиксируется подтверждённое фото начало
14:30, окончание не придумывается. Администратор может уточнить любую неделю.

## Реализация и применение

Миграции схемы: `20261109085327_create_class_schedule_weeks.sql` и
`20261109085345_create_class_schedule_entries.sql`. Первичное заполнение:
`20261109085441_seed_grade_7_weekly_schedule.sql`. Заполнение рассчитано на
существующий 7 класс с ID `60000000-0000-4000-8000-000000000001` и десять
назначенных предметов основной программы. При несовпадении исходных данных
оно прерывается с ошибкой, а не создаёт неполное расписание.

На чистой установке создаются 40 недель и 1170 занятий. Даты занятий
ограничены 01.09.2026–31.05.2027. Пустые дни до и после года в неполных
неделях недоступны для добавления. Выходные остаются пустыми, но администратор
может добавить занятия на них. Копирование начальных данных выполняется
однократно; недели, уже существующие при применении seed-миграции, пропускаются.

API: `GET /api/v1/classes/{classId}/schedule/{weekStart}` и `PUT` по тому же
адресу. `weekStart` — дата понедельника. Пустая новая неделя имеет `revision=0`.
При сохранении передаются текущая revision и полный список занятий.
Проверка версии и запись сериализованы блокировкой строки класса; несовпадение
версии возвращает `409`. Для сохранённых занятий передаются существующие ID,
для новых — пустая строка. Передать ID занятия из другой недели нельзя.

Интерфейс: «Классы» → нужный класс → «Расписание». Применение диалога меняет
локальный черновик; запись в БД выполняется кнопкой «Сохранить неделю».
Несохранённые изменения можно отменить. При конфликте сохранения черновик
сохраняется на экране, а загрузка недели заново выполняется явно.

Перед применением миграций нужна резервная копия. Автоматический Down
начального заполнения запрещён, поскольку он мог бы стереть уже исправленные
недели. Возврат к предыдущим данным требует отдельного плана по резервной копии.
Рабочая база при разработке не изменяется; миграции проверяются на отдельном PostgreSQL.

Выполненные проверки: весь клиентский набор (103 теста), ESLint и production-сборка;
`make test`, `make lint`, `make generate` (повторный результат совпадает),
`make build`, `make migrate-validate`. Новые интеграционные сценарии
`TestClassScheduleAccessIsolationAndValidation` и
`TestSeededScheduleIncludesHolidaysAndPreservesEdits` выполнены на отдельной
базе PostgreSQL 17. Они проверяют права, принадлежность предметов, границы дат,
изоляцию недель, устаревшую версию, занятия групп и сохранность правок при
повторном выполнении начального заполнения.
